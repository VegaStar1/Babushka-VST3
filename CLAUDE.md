# Babushka

VST3-эмуляция полумодульного аналогового синтезатора (прототип: Moog Grandmother, 2018). Название, код и интерфейс собственные; имя и логотип Moog не используются нигде: ни в названии, ни в интерфейсе, ни в идентификаторах, ни в коммитах-описаниях для пользователей. Цель: коммерческий продукт (компания NUWMUN, JUCE-проект `Babushka`, код плагина `Bbsk`).

Подробное описание модулей, результатов проверок и калибровки: `README.md`. Не дублируй его здесь, поддерживай актуальным там.

## Правила работы

- С автором общайся по-русски. Код, идентификаторы, имена файлов, сообщения коммитов остаются на английском.
- Перед крупным изменением коротко опиши план и жди подтверждения.
- Не придумывай факты о железе. Неизвестное помечай в коде комментарием `ASSUMPTION` с пояснением; список таких мест ведётся в разделе «Что калибровать» в `README.md`.
- Коммиты маленькие, по одной теме: что и зачем.
- Автор не хранит проект на своём компьютере. Источник правды: GitHub. Работа идёт в облачных сессиях Claude Code, в том числе со смартфона. Ничего не требуй устанавливать локально.

## Статус

Готово: ядро звука (осцилляторы, микшер, лестничный фильтр, огибающая, VCA, Mod Osc, пружинный ревербератор, контроллер), арпеджиатор/секвенсор, внешний вход (sidechain), передискретизация 1×/2×/4×.

Следующие этапы: патч-панель (41 точка) и финальный интерфейс. Не начинай их без согласования с автором. Пока интерфейс служебный.

## Структура

- `Source/dsp/` — DSP-ядро на чистом C++ без зависимости от JUCE (`Engine.h` собирает голос, остальные файлы: `Oscillator.h`, `LadderFilter.h`, `Envelope.h`, `Lfo.h`, `SpringReverb.h`, `Decimator.h`, `ArpSeq.h`, `Common.h`). Держи его независимым от JUCE: так его можно тестировать отдельно и быстро.
- `Source/PluginProcessor.*`, `Source/PluginEditor.*` — JUCE-обвязка: параметры, MIDI, состояние, интерфейс.
- `tools/render.cpp` — офлайн-рендер и тесты DSP без JUCE (`babushka_render`).
- `tools/hosttest/Main.cpp` — headless-тест собранного VST3 как в DAW (включается `-DBABUSHKA_HOST_TEST=ON`).
- `.github/workflows/build.yml` — сборка в GitHub Actions.

## Сборка и проверка

Быстрая проверка DSP (3 секунды, без JUCE и без скачивания; работает в облачной среде):

```bash
g++ -std=c++17 -O2 -I Source tools/render.cpp -o babushka_render
mkdir -p out && ./babushka_render out | tee tests.log
grep "arp/seq tests: ALL PASSED" tests.log
grep "no NaN/Inf" tests.log
```

Полная сборка плагина (JUCE 8.0.4 скачивается автоматически, CMake ≥ 3.22, C++17):

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release --target Babushka_VST3
```

Облачная среда работает на Linux. Готовые `.vst3` под Windows и macOS собирает GitHub Actions; артефакты берутся из запуска во вкладке Actions: `Babushka-Windows-VST3`, `Babushka-Windows-Standalone`, `Babushka-macOS-VST3`. После пуша проверь статус сборки; если упала, прочитай лог и исправь. Держи `COPY_PLUGIN_AFTER_BUILD FALSE`.

CI проверяет только то, что DSP-тесты проходят (они собираются вместе с Windows-сборкой). Перед пушем DSP-изменений прогоняй быструю проверку выше.

## Требования к DSP

- Аудиопоток (`processBlock` и всё, что из него вызывается): никаких выделений памяти, блокировок, ввода-вывода и исключений.
- Частота дискретизации не зашита в константы; поведение звука не должно сильно зависеть от неё.
- Нелинейности (насыщение, самовозбуждение фильтра) моделируются с защитой от алиасинга: передискретизация или антиалиасинг, выбор обосновывай в комментарии.
- Параметры через `AudioProcessorValueTreeState`, значения сглаживаются, чтобы не было щелчков.
- Состояние плагина и последовательности секвенсора сохраняются и восстанавливаются; не ломай совместимость сохранённых проектов без причины.
- Любое изменение DSP сопровождай тестом в `tools/render.cpp`, если поведение можно проверить числами.

## Звук проверяет автор

Claude Code не слышит звук. После изменения звучания перечисли, что именно автору послушать в DAW, и укажи, из какого запуска Actions взять сборку. Не утверждай, что звук «стал лучше», опираясь только на тесты.

## Источники и юридические границы

У автора нет ни Grandmother, ни записей с него. Эмуляция строится только на открытых источниках: научные публикации по виртуально-аналоговому моделированию, общедоступные схемотехнические описания, публичное руководство пользователя.

Запрещено, потому что продукт коммерческий:

- копировать код, прошивки, схемы или сэмплы Moog или других закрытых проектов;
- использовать название, логотип, шрифты и графику Moog;
- использовать GPL-код (DSP написан с нуля по публикациям, перечисленным в `README.md`);
- добавлять зависимости без проверки лицензии: она должна допускать коммерческое распространение закрытого продукта.

Для каждого заимствованного алгоритма записывай источник и лицензию в `README.md` (раздел «Лицензии»).

## Открытые вопросы

- Коммерческая лицензия JUCE перед релизом (AGPLv3 для закрытого продукта не подходит).
- Согласие с лицензией VST3 SDK и торговая марка VST (Steinberg).
- Подпись и нотаризация macOS-сборок, подпись Windows-сборок.
- Способ распространения и защиты копий.
- Формат AU, AAX: нужны ли.
