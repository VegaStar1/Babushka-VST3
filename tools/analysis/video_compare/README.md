# Сравнение с записью железа (video_compare)

Плагин играет ту же партию, что записана на железе, и обе записи измеряются одинаково.

```
cmake --build build --target babushka_render
python3 tools/analysis/video_compare/compare.py <запись.wav> tools/analysis/video_compare/env_sync_sweep.part \
        --start 19.0 --end 30.6 --out video_compare_out
```

Нужны numpy и scipy (matplotlib — для `report.png`). Код возврата 1, если метрика вышла за предел: после правок звука
сравнение работает как регрессионный тест. В папке результата: `metrics.txt`, `report.png` (спектрограммы, свип, громкость),
`hardware.wav` и `plugin_matched.wav` (громкость выровнена) для прослушивания.

## Файл партии (`*.part`)

Формат `babushka_render --play <part> <out.wav>`: строки `set <параметр> <значение>` (имена полей `Params` в `Engine.h`),
`patch <кабели>` (текстовый формат `Patch.h`), `length <с>`, `on <с> <клавиша>` / `off <с> <клавиша>`; `#` — комментарий.

## Что измеряется

Кадры по 10 мс:

- бас — высота осциллятора 1 (сумма гармоник, 30–170 Гц);
- свип — самый сильный пик выше 3,5-й гармоники баса; с SYNC это частота осциллятора 2. Сравнивается
  `r = log2(свип / бас)` — на сколько октав осциллятор 2 выше первого, от нажатой клавиши не зависит;
- громкость и средний спектр по полуоктавам (нормирован на бас 90–180 Гц).

| Метрика | Предел |
|---|---|
| доля времени, когда звучит (> −40 дБ), разница с железом | ≤ 15 % |
| громкость по кадрам, rms разницы | ≤ 10 дБ |
| свип r(t), rms разницы | ≤ 0,8 окт |
| свип найден там, где он есть у железа | ≥ 60 % |
| спектр 200 Гц – 8 кГц, rms разницы | ≤ 4 дБ |

## env_sync_sweep.part

Патч из видео Moog о Grandmother: +ENV OUT → OSC 2 PITCH IN, SYNC включён, VCA в KB RLS, SUSTAIN низко. Сама запись
(звуковая дорожка видео, 19,0–30,6 с) в репозиторий не входит.

Как получена партия:

- ноты — по высоте баса записи (железо выше строя на ≈18 центов, отсюда Fine Tune 0,18); игра деташе: в записи перед
  сменой ноты VCA проседает на 4–6 дБ, а свип каждый раз заново начинает атаку с текущего уровня;
- осциллятор 2 на 4' (на две октавы выше первого на 16'): с этой высоты начинается каждый свип;
- огибающая подобрана по свипу моделью огибающей плагина: атака — RC-кривая с τ ≈ 0,8 с (ошибка подгонки 0,05 окт на
  трёх атаках «с нуля»), релиз τ ≈ 0,24 с;
- CUTOFF 1,0: при нём средний спектр совпадает с записью (2,3 дБ); при положении ручки на фото из видео (около часа дня)
  плагин на 20–30 дБ темнее выше 200 Гц. Открытый вопрос: либо ручка во время записи стояла иначе, либо отличается шкала.

Результат на этой записи: до исправления KB RLS (VCA закрывался по SUSTAIN) плагин звучал 17 % времени против 92 % у железа,
все пять проверок FAIL; после — все в пределах (84 %, громкость 8,0 дБ, свип 0,56 окт, спектр 2,3 дБ).

Не решено: атака железа стремится к +7,2 окт от начала свипа, у плагина (8 В × 1,3) — к +10,4 окт. Партия чуть лучше
совпадает, если огибающую ослабить до ×0,69 (свип 0,51 окт вместо 0,56), но по одной записи это не отличить от другого
запаса атаки. Нужна запись: SUSTAIN максимум, короткая атака, долгая нота — плато высоты покажет размах огибающей в октавах.
